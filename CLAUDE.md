# CLAUDE.md — permanent rules for every Mini Commandoes session

Read order at session start: `CLAUDE.md` → `handover.md` → `PROJECT.md` → relevant part of `blueprint.md`.

## Purpose & stack
Original 2D multiplayer commando game, **Android first**, then desktop. Godot **4.6.3** (pinned), GDScript, `gl_compatibility`. Owner works from an Android phone + GitHub + GitHub Actions only: never require a PC/IDE/editor.

## Folder & naming rules
- Layout is defined in `blueprint.md §4`; don't invent top-level folders.
- Files/folders `snake_case`; classes `PascalCase`; constants `UPPER_SNAKE`; private members `_leading`; signals past tense (`hit_taken`).
- Content ids are lowercase snake strings in `data/*.json`. Content lives in data, **never hard-coded** in scripts.
- No user-visible string literals in gameplay code (use string tables once added).
- Scripts ≤ ~400 lines; split by responsibility. No duplicate systems.

## Coding rules
- Typed GDScript (`var x: int`, return types). No per-frame allocations in sim loops. Pool projectiles, pickups, particles, floating text.
- Simulation code does not reference UI/view nodes. Sim must be runnable headless.
- Host-authoritative: clients send inputs only; never trust client HP/ammo/score/cooldowns.
- No `class_name`; use `const X := preload("res://…")` and `extends "res://…"` (blueprint D9). Lambdas capture locals **by value**: create nodes first, then connect; avoid multi-line lambdas followed by more call arguments (use `Callable.bind` / named methods). No autoload references inside `const` expressions.
- No new dependency/addon without a decision record in `blueprint.md §0`.

## Git & branches
- `main` = stable (always builds). Work on `dev/<topic>`; merge only when CI green. Small logical commits: `type(scope): message` (`feat`, `fix`, `docs`, `ci`, `test`, `chore`).
- Never delete or rewrite a working system without a passing regression run. Never force-push `main`.
- Say which branch you are on in `handover.md`.

## Testing & verification (no-fake-completion)
- Every feature needs: implementation → static/unit check → CI build → runtime check → device check (if applicable) → docs. Record in `PROJECT.md`.
- Allowed status words only: **Planned, In progress, Implemented, Build verified, Runtime verified, Device verified, Network verified, Production ready**. Anything not backed by evidence is `Implemented` at best.
- Label clearly: **UI PLACEHOLDER** vs **FUNCTIONAL FEATURE** vs **TESTED FEATURE**. Placeholders go in the placeholder tracker (`PROJECT.md`).
- After a fix: re-test affected area + related regression, then move on. Do not loop on already-proven areas.
- Simulated multiplayer ≠ real multiplayer. Report **SIMULATED 40 PLAYER TEST** and **REAL 40 DEVICE PLAYER TEST** separately.
- Never invent results. If the sandbox can't run it (no Godot/Android there), say so.

## CI & Android build rules
- Workflows pinned to exact versions (see `blueprint.md §30`). Downloads checksum-verified.
- Debug APK = `DEBUG`, never "release". Release only from signed tag workflow.
- `.github/workflows/*` cannot be pushed by the Actions token: owner pastes workflow files in the GitHub web editor. Claude should output complete file contents when workflows change.
- Keep every workflow `workflow_dispatch`-triggerable (phone-friendly).

## Multiplayer rules
- Protocol has a version field; mismatch = clear error. Channel plan in `blueprint.md §19`. Manual IP join must always work even if discovery fails.
- Any new replicated state needs: snapshot layout entry, bandwidth estimate update, and a test.

## Asset & audio rules
- Everything shipped is original or license-clean and recorded in `ASSET_SOURCES.md` **before** it is committed. No assets from Mini Militia or any other game. No downloaded audio/art without a license record. Fonts: SIL OFL or similar only.
- Audio is generated by `tools/gen_audio.py` (stdlib); human listening review required.

## Security rules
- No secrets in repo, logs, chat. Keystore only via GitHub Secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_USER`, `ANDROID_KEYSTORE_PASSWORD`; names only here). `tools/validate_repo.py` blocks key files and hardcoded passwords.
- Validate all network input (sizes, ranges, rates). Save files: atomic write + backup.

## Performance rules
Stable FPS, low memory, responsive controls, stable netcode, reliable builds beat visuals. Budgets in `blueprint.md §28`. Claim nothing unmeasured.

## Documentation & change protocol
- Architecture change ⇒ explain why → update `blueprint.md` → update this file if rules change → update `handover.md` → then implement.
- Every subsystem gets `docs/<subsystem>.md` when implemented. Update `handover.md` at the end of every phase/session.
- Keep a short changelog in `PROJECT.md`. Bugs follow the bug template in `PROJECT.md` (ID, title, severity, repro, expected, actual, status, fix commit, verification). Never mark fixed without verification.

## Originality
Genre inspiration only. Never copy code, sprites, characters, maps, music, sounds, UI, logos, names from Mini Militia or others.

## Release requirements
Signed release build, version/build/sha shown in About, checksums, release notes, fresh-install + upgrade test, soak test, store/legal quick check, final QA report. Desktop work starts only after Android V1 acceptance (`PROJECT.md`) is verified.
